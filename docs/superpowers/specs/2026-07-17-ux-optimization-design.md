# 四季番约 · 用户体验与功能设计优化方案

> 分析日期：2026-07-17
> 方法：以用户旅程为主线的全面体验审查

## 一、项目现状概述

四季番约（萤火番舍 · AniGlow）是一个综合性动漫社区平台，采用 Nuxt 3 + Spring Boot 全栈架构，核心功能包括：

- 番剧浏览（Jikan API 同步 + 贝叶斯评分排序）
- 评分与评论系统（星级打分 + 分类筛选 + 二级回复）
- 萤火投票机制（每日任务赚取票数）
- AIGC 角色对话（火山方舟 API，WeChat风格移动端 + Galgame桌面端）
- 社区论坛（4个固定盒子 + 图片发帖 + 灯箱查看）
- Authing OAuth 登录 + JWT 鉴权
- PWA 支持

**视觉风格**：小清新、温柔、动漫风 — 奶油白背景 + 琉璃玻璃态 + 萤火绿点缀 + 大圆角 + 弥散阴影。

## 二、分析方法

以四条核心用户旅程为主线，在每个旅程节点上审查体验的完整性和流畅度：

1. **发现之旅** — 游客 → 浏览 → 被吸引 → 注册
2. **深入之旅** — 用户 → 搜索/发现番剧 → 详情 → 评分/投票
3. **社交之旅** — 用户 → 社区 → 讨论 → 归属感
4. **回流之旅** — 离开后 → 每日任务 → AIGC → 持续参与

辅以跨旅程维度检查（导航一致性、加载/空状态、模块连接、错误处理等）。

## 三、旅程分析

### 3.1 发现之旅（首页 & 导航 & 番剧浏览）

**现状**：Hero 区（左卡片 + 右轮播海报）→ 向下滚动提示 → 本周热门番剧网格 → 特色板块 → 页脚。

**发现的问题**：

| # | 问题 | 严重程度 |
|---|------|----------|
| 1 | 桌面导航搜索按钮点击无任何响应，是"死按钮" | 中 |
| 2 | 移动端底部导航只有 5 项（缺少「每日」），桌面端有 6 项 | 高 |
| 3 | Hero 区 CTA 层级模糊：「随机一部番」和「AIGC投票」都不是新用户的首要行动路径，缺少「开始浏览番剧」的主 CTA | 中 |
| 4 | 注册后无任何欢迎引导或偏好设置流程，用户不知道能做什么 | 中 |
| 5 | 首页内容在首屏后迅速衰减：只有 12 张番剧卡片 + 3 个静态引导卡片，无动态内容、无个性化推荐 | 中 |

**优化建议**：

- P0: 移动端底部导航增加「每日」入口（6 项布局或替换低使用率项）
- P0: 导航搜索按钮点击后弹出搜索浮层或跳转到 `/anime`（已有搜索功能）
- P1: Hero 区增加「浏览番剧」按钮，将「AIGC投票」改为次要样式
- P1: 新用户注册后弹出轻量引导页：选 3-5 个偏好标签 → 推荐 3 部番剧
- P2: 特色板块改为动态内容（今日投票排行 Top3、社区热帖预览、新番上线提醒）

---

### 3.2 深入之旅（番剧详情 & 评分 & 投票）

**现状**：模糊封面 Hero → 海报卡片 + 元信息 → AIGC角色卡片（如有）→ 评分讨论区 → 侧栏（基本信息 + 同好也在看）。

**发现的问题**：

| # | 问题 | 严重程度 |
|---|------|----------|
| 1 | 番剧详情页没有任何投票入口 — 用户看完番剧、写完评价后最想投票的时刻却无处可投 | 高 |
| 2 | 番剧详情页与社区完全割裂 — 没有「去社区讨论这部番」的入口或相关帖子预览 | 高 |
| 3 | 缺少「想看/在看/看过/已弃」的追番状态标记功能 | 中 |
| 4 | 评分提交后页面无反馈引导 — 用户不知道该做什么下一步 | 低 |
| 5 | 「同好也在看」推荐逻辑不透明，无说明标签 | 低 |

**优化建议**：

- P0: 番剧详情页右侧栏增加「投一票」按钮 + 显示当前萤火票数
- P1: 详情页增加「社区讨论」板块，展示该番剧关联的社区帖子预览（利用 CommunityDto.relatedAnimeId）
- P2: 增加追番状态标记（想看/在看/看过/已弃），存入用户数据用于个性化推荐
- P2: 评分提交后弹出轻提示：「你的评分已计入排行 → 去看看排名」
- P2: 相关推荐增加标签说明：「类型相似」「评分接近」「同好也在看」

---

### 3.3 社交之旅（社区 & 帖子 & 互动）

**现状**：桌面端侧边栏 + 帖子列表（朋友圈风格）→ 帖子详情（封面 + 图片网格 + 灯箱 + 回复区）→ 发帖弹窗（支持图片上传）。

**发现的问题**：

| # | 问题 | 严重程度 |
|---|------|----------|
| 1 | 番剧与社区是独立孤岛 — CommunityDto 有 relatedAnimeId 字段但未在番剧详情页使用 | 高 |
| 2 | 社区固定为 4 个盒子（番剧/漫画/游戏/Vibe Coding），不可扩展 | 中 |
| 3 | 完全没有通知系统 — 无点赞通知、回复通知、@提及 | 高 |
| 4 | 用户主页功能极其单薄 — `/user/posts` 只能看帖子列表，无追番、无评分历史、无个人简介 | 中 |
| 5 | 桌面端侧边栏可以快速切换社区，移动端必须回到广场再进入 — 导航体验不一致 | 低 |

**优化建议**：

- P1: 实现通知中心（回复通知、点赞通知），顶部导航用户头像加未读小红点
- P1: 番剧详情页增加「社区讨论」板块（与 3.2 的第 2 点协同实现）
- P1: 丰富用户主页：追番列表 + 评分历史 + 发帖记录 + 动态时间线
- P2: 短期：为热门番剧自动生成专属讨论区；长期：允许用户创建社区
- P2: 帖子详情页增加社区面包屑导航，移动端增加快捷切换社区入口

---

### 3.4 回流之旅（留存 & 付费转化）

**现状**：每日任务系统（3 个任务赚萤火票）→ AIGC 角色聊天（多角色 + 情绪表达）→ 会员付费入口（角落 FAB 按钮）。

**发现的问题**：

| # | 问题 | 严重程度 |
|---|------|----------|
| 1 | 移动端底部导航缺少「每日」入口 — 核心留存机制在手机上不可见（与 3.1 第 2 点相同） | 高 |
| 2 | 会员付费入口是一个角落里的「賞」字 FAB 按钮，无文字说明，绝大多数用户不会点击 | 中 |
| 3 | AIGC 对话无配额感知 — 免费/付费的剩余次数不可见，突然被限制时体验很差 | 高 |
| 4 | 缺少个性化回流动机 — 无浏览历史、无个性化推荐、无新番提醒 | 中 |
| 5 | PWA 安装提示时机不明显 — 应该在用户完成有价值操作后触发 | 低 |

**优化建议**：

- P0: AIGC 聊天页面显示剩余对话次数 + 每日重置倒计时
- P1: 会员付费入口优化：AIGC 配额用尽时自然引导 → 付费弹窗（而非隐藏 FAB）
- P1: 首页增加「继续探索」板块（最近浏览 + 基于评分的推荐）
- P2: PWA 安装提示改为在评分成功/发帖成功后触发
- P2: 每日任务完成后弹出分享引导：「今天完成了全部任务，邀请同好一起来 →」

## 四、跨旅程系统性问题

| # | 问题 | 说明 |
|---|------|------|
| S1 | 导航不一致 | 桌面 6 项 vs 移动 5 项；搜索按钮装饰性 |
| S2 | 加载状态不统一 | 首页/排行有骨架屏，其他页面使用简单 spinner 或空白 |
| S3 | 空状态不统一 | 社区有精美空状态引导，其他页面风格各异 |
| S4 | 模块间无连接 | 番剧/社区/AIGC/排行各自孤立，用户无法自然流转 |
| S5 | 错误静默吞没 | 所有 composable 的 API 失败静默返回空数组，用户无法区分「真为空」和「加载失败」 |
| S6 | 无障碍缺失 | 焦点指示器、skip-link、键盘导航、语义化 ARIA 标签均不完善 |

## 六、技术注意事项

### 6.1 通知系统

- 需要新增后端 `Notification` 实体和 `/api/notifications` 端点
- 前端使用轮询或 SSE 获取未读计数
- 存储于 MySQL，高频通知考虑 Redis 缓存

### 6.2 番剧 ↔ 社区关联

- `CommunityDto.relatedAnimeId` 字段已存在，需要后端提供 `GET /api/communities/posts/by-anime/{animeId}` 端点
- 前端在番剧详情页新增板块，展示最近的 3-5 条相关帖子

### 6.3 AIGC 配额管理

- 后端 `AgentService` 已有限流逻辑，需要新增 `GET /api/agent/quota` 端点返回剩余次数
- 前端在 AIGC 聊天页顶部/底部显示配额条

### 6.4 追番标记

- 需要新增后端 `UserAnimeStatus` 实体（userId + animeId + status + updatedAt）
- 新增 `PUT /api/user/anime-status` 和 `GET /api/user/anime-status` 端点

### 6.5 个性化推荐（P2）

- 基于追番标记 + 评分历史的协同过滤或简单的类型匹配
- 初期可用简单的「同类型高分番剧」替代复杂的推荐算法
